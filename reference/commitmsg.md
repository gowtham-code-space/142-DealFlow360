# Commit Message Convention

This project follows a consistent commit message format to keep history clean and readable.

## Format

```
type: short description
```

## Types

| Type       | Description                              |
|------------|-------------------------------------------|
| `feat`     | Add a new feature                         |
| `fix`      | Fix a bug                                 |
| `refactor` | Improve code without changing behavior    |
| `perf`     | Improve performance                       |
| `style`    | Formatting changes only                   |
| `docs`     | Documentation updates                     |
| `test`     | Add or update tests                       |
| `chore`    | Maintenance tasks                         |
| `build`    | Build system or dependency changes        |
| `ci`       | CI/CD pipeline changes                    |

## Examples

```
feat: add quotation approval workflow
feat: add customer negotiation portal
feat: implement warehouse allocation

fix: resolve approval state issue
fix: correct stock calculation

refactor: simplify quotation service

perf: optimize quotation risk calculation

style: format quotation components

docs: update project documentation

test: add quotation validation tests

chore: update dependencies

build: configure production build

ci: add automated test workflow
```

| Type       | Meaning                    |
|------------|-----------------------------|
| `feat`     | New functionality           |

| `perf`     | Performance improvement      |
| `style`    | Formatting only              |

| `test`     | Testing                       |
| `chore`    | Maintenance                   |
